## 8. 已知缺陷与风险（务必与上面数字一起读）

1. **NL 丢失 cross 语义**：`nl_text` 编译出的 YAML 把「上穿/下穿/金叉/死叉」落成纯 `>` / `<` 比较，
   条件在区间内持续为真，信号与真正「穿越事件」不同。因此 item1 / item3 的收益与交易数
   **偏多是口径产物，不是 bug 修复**。wizard 前端有 `crosses_above` 但 NL 路径未使用。
   本轮只记录、不修（不改业务代码的硬约束）。
2. **P2-14 未生效**：系统 worker（8124）未重启，参数变体相关修复未进入本轮执行路径。
3. **`.env.saas-staging` / `aghuice_local` 缺失**：staging 配置在本机不可用，故另建 `qre_stress_2611`。
4. **`worker_cpu_pct` 是 `ps` 生命周期均值**，不是瞬时 CPU%；`postgres` 全进程 RSS 求和会重复计入共享内存，
   两个内存数字都偏保守/偏高，只能横向对比。
5. **`truncated` 产物**：逐产物名检查，出现即在下文标注。
6. **临时进程**：app(66791/66788) 与 `worker --once` 为临时进程，压测结束后清理；
   `qre_stress_2611` 库保留不删（含 job 记录，供复盘）。
7. **上传目录未隔离（已造成一次全量测试污染）**：临时 SaaS app 未显式设置
   `SAAS_UPLOAD_DIR`，产物写进了仓库默认 `outputs/saas_uploads`，导致主 Agent 跑全量
   pytest 时 `test_gui_saas.py::TestResultsApi::test_detail_endpoints` 读到不属于它的
   `risk_report.json` 而失败。单测复跑通过；主 Agent 已改用
   `SAAS_UPLOAD_DIR=.tmp/test-uploads-isolated` 重跑全量。
   **后续压测必须显式隔离上传目录**，例如：
   `SAAS_UPLOAD_DIR=.tmp/stress-2026-11-02/uploads uv run qre saas ...`。
   **测试侧已修复根因**：`tests/test_gui_saas.py::TestResultsApi._completed_job`
   现在显式设置 `SAAS_UPLOAD_DIR=tmp_path/uploads`，不再读取仓库默认 `outputs/saas_uploads`。
8. **全量单跑时长无法由冒烟线性外推**：三项的实际耗时只以本轮实测为准。
