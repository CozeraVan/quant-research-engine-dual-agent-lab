## 第三轮：跨策略对账后确认真实口径缺陷并修复

此前只验证了单个 run 内的复权与均值算术，结论不完整。跨 run 对同一区间 `2009-01-04` 附近至 `2026-10-30` 的5201只全市场结果比较后，买入持有均值出现 −2.69%、+12.05%、+12.09%、+12.30% 等多个值，且大量逐股基准不同，证明其确实受策略影响。

根因有三处：

1. `ResearchFrameAssembler.build()` 对行情与因子做 inner join；不同因子覆盖区间删除不同 K 线，首末行情因而随策略变化。
2. 单股与增量持有基准使用策略的 `entry_price_column`/`mark_price_column`，而非固定行情口径。
3. shared 补齐路径只统计实际交易股票，而非完整回测宇宙。

已修复：因子改 left join，缺因子保留行情并产生 NaN；持有基准统一首根开盘→末根收盘；shared 改为回测宇宙等权。历史产物不回写、不重跑。六项定向缺陷测试先红后绿；相关回归288 passed/14 skipped；合成小样本证明两种不同因子覆盖下均为首开盘10→末收盘13.5=+35%。证据 `.tmp/buy-hold-invariance-smoke.json`。

## 第四轮：NL 根因处置与持有基准合同

历史服务日志只能证明目标 run 前没有 `/api/nl_compile`，不能据此断言用户当时是否点击、浏览器为何未发请求。根本设计缺陷是 NL 编译与运行是两条独立路径，且编辑器预载布林带 YAML。最终处置不是要求用户记得另点按钮，而是点击「运行回测」即自动编译当前原文；成功结果才进入校验/冒烟/正式回测，失败可见并停止。真实浏览器覆盖自动编译、改描述重编译、改YAML重编译和失败不运行，零 pageerror；证据 `.tmp/nl-run-auto-compile-browser.json`。

持有基准的合同为：对给定数据快照、回测区间和股票宇宙，每股取区间内首个有效交易日的复权开盘价与最后一个有效交易日的复权收盘价，`R_i = P_last_close_adj / P_first_open_adj - 1`，再对全部有有效边界的股票等权算术平均。无交易股票必须包含；停牌/退市导致末日无交易时使用其最后有效收盘并保留数据边界含义；新股从上市后的首个有效交易日开始。它只在相同宇宙、区间和行情快照下固定，不承诺跨不同日期或数据更新后仍相同。
