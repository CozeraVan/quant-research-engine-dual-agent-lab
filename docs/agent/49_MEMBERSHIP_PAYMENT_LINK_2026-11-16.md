# 49. 分层会员付费链路（2026-11-16）

## 当前决策

用户改定“分层会员制”，不再采用月费积分 Token Plan。本文件只探究支付到权益的打通方式，不制定档位、价格或权限差异，不接真实支付。

## 复用现有系统

- 身份：自建手机号 + 密码/短信，Bearer session。
- 用户权益：`users.tier`、`member_since`、`member_expire_at`。
- 权限执行：`tier_policies` + 现有拦截点；网页和 MCP 最终必须读取同一权益来源。
- 运营：9090 展示真实订单、支付状态、会员生效区间和异常对账，不另造权限值。

## 首版渠道建议

优先微信 Native PC 扫码，单次购买固定期限会员；不做自动续费、不做积分、不做充值余额。支付宝电脑网站支付可作为第二渠道。微信支付官方要求支付结果以服务端通知或主动查单为准，退款另有异步结果通知，因此不能只依赖浏览器“支付成功”。

## 端到端链路

1. **套餐展示**：服务端商品目录定义 SKU、tier、天数、价格；页面不自行计算价格。
2. **创建订单**：登录用户选择 SKU → 服务端创建唯一本地订单，状态 `created/pending`，金额和权益以服务端为准。
3. **渠道下单**：服务端调用 Native 下单，保存 `out_trade_no`、渠道、`code_url`、过期时间；前端只展示二维码。
4. **等待支付**：页面轮询本地订单，不直接信任渠道页面跳转。
5. **支付回调**：公网通知 → 验证签名/证书 → 校验商户号、订单号、金额、币种 → 记录原始通知 ID → 事务内幂等推进订单。
6. **权益生效**：同一事务写订单 `paid`、会员有效期和权益变更历史。首次购买从支付成功起算；续费从当前到期日与当前时间较晚者顺延。
7. **用户可见**：页面轮询到 paid 后显示会员与到期时间；MCP 后续请求读相同 tier/有效期。会员额度按**支付服务周期**重置，不按自然月1日统一重置；免费游客每日1次，登录用户每周期10次10股/10年以内测试且不可全期。
8. **主动查单兜底**：回调超时或投递失败时，服务端按本地订单主动查询，不重复发放权益。
9. **退款**：退款申请/渠道受理/成功分状态记录；退款成功后按已公示规则降级或收回剩余权益，保留审计历史。
10. **对账**：每日渠道账单 vs 本地订单，识别漏单、重复、金额不符、已支付未生效、退款未降级，进入 9090 异常队列。

## 最小数据模型（规划，未创建）

- `membership_products`：SKU、tier、天数、价格、启用状态、版本。
- `membership_orders`：本地订单号、用户、SKU 快照、金额、渠道、状态、支付/到期时间、渠道订单号。
- `payment_events`：渠道通知 ID、事件类型、验签结果、处理结果；唯一约束防重复回调。
- `membership_entitlements`：订单、tier、生效/到期、状态、撤销原因；支撑续费与退款审计。
- `refunds`：原订单、退款单、金额、渠道状态、完成时间。

订单状态建议：`created → pending → paid → fulfilled`；另有 `expired/closed/refunding/refunded`。支付成功与权益发放需能安全重试，不能因一次模板或通知失败永久卡死。

## 安全与正确性红线

- 金额、tier、期限、回调地址都由服务端配置，禁止信任前端。
- 密钥和证书只进 ECS 受控环境，不进仓库/浏览器/日志。
- 回调验签 + 金额/商户/订单校验 + 数据库唯一约束 + 事务幂等缺一不可。
- 不根据 User-Agent、return_url、截图或用户自述开通会员。
- 同一订单重复通知、重复查单、重复投递不得重复延长会员。
- 真实上线前完成过期、续费、重复回调、掉单补查、退款和跨账号测试。

## 实施顺序（待用户后续批准）

1. 只读商品/订单模型和状态机，接沙箱或模拟渠道。
2. Native 下单、二维码、验签回调、主动查单、幂等权益。
3. 到期降级、续费顺延、退款和对账。
4. 9090 运营与用户订单页，网页/MCP 权限一致性。
5. 主体、备案、收单、税票和协议就绪后，小额真实支付→退款灰度。

当前不接支付、不改数据库、不改会员档位。跨区间/股票数的权益换算参考另见 `50_BACKTEST_WEIGHT_MATRIX_2026-11-16.md`；SU 仅为分层设计参考，不是恢复积分制。
