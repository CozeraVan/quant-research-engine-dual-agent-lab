# CR-2026-11-19 全量回测与日更互斥调度

## 背景

job379/380未遇日更，耗时45–49分钟；job381/382与16:30后的行情、Alpha191及panel因子日更重叠，耗时100–117分钟。后两组交易数反而更少，瓶颈是CPU、PostgreSQL与I/O争用。并行还可能让流式回测读取到更新中的数据快照。

## 方案

- 采用本机文件锁 `/tmp/qre-market-refresh.lock`（可用环境变量覆盖用于测试）。锁不保存业务状态，重启后无 stale lock 问题。
- `quant-ts-daily`、`indicators-tushare-daily`、`alpha191-daily`、`panel-factors-daily` 自动入口以及日更中心对应手动入口持有排他锁，等待在途全量结束才启动。
- worker heavy 槽从认领到执行、回传完成持有共享锁；日更运行/等待时不认领新全量。多个全量仍可按既有内存预算并行，轻量槽保持不变。
- 使用 systemd drop-in 包装既有官方命令，不修改 quant_ts/indicators_tushare 项目代码，不改回测计算语义，不重跑已有任务。

## 验证

TDD 覆盖共享锁可并行、排他锁阻断新全量、在途全量阻断日更、手动日更等待、锁释放后恢复，以及四个自动单元配置。运行worker/日更回归后部署本机服务，使用短进程实测互斥，不启动全量回测或真实日更。
