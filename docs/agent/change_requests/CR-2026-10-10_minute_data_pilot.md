## 0. 数据形态确认（40 文件全量扫描）

| 项 | 结论 |
|---|---|
| 格式 | **A 型仅 1 个**（`000001SZ.csv`：`trade_time,open,close,high,low,vol,amount,pre_close`）；**B 型 39 个**（MT5 风格 `<DATE>,<TIME>,<OPEN>,...,<TICKVOL>,<VOL>,<SPREAD>`） |
| 分隔符 | 两者均为 **Tab**（非逗号，read_csv 必须 `sep="\t"`） |
| 时间网格 | A 型：09:31–11:30 + 13:01–15:00，240 根/日，且 95% 的交易日多一根 **09:30 集合竞价 bar**（共 241 根）；B 型：09:30–11:30 + 13:01–15:00，固定 **241 根/日，缺 13:00 标签**（首根 09:30 应理解为 09:30–09:31 区间） |
| 文件名 | `000001SZ.csv`（无点）vs `000002.SZ.csv`（带点），仅 1 个异类 |
| 区间 | A 型 2009-01-05 ~ 2021-12-31；**全部 39 个 B 型文件统一止于 2021-06-28/29**（并非 2021-12） |
| 字段差异 | B 型**没有 amount（成交额）字段**；`<VOL>` 与 `<TICKVOL>` 完全相等；`<SPREAD>` 恒为 0 |

## 1. 数据正确性验证（抽样 5 只：000001.SZ / 000002.SZ / 000333.SZ / 000651.SZ / 002008.SZ）

逐股票结论表（全部 76 万行级别全量检查，非采样）：

| 指标 | 000001.SZ (A) | 000002.SZ (B) | 000333.SZ (B) | 000651.SZ (B) | 002008.SZ (B) |
|---|---|---|---|---|---|
| 行数 | 761,404 | 730,712 | 455,731（2013 上市起） | 730,712 | 731,194 |
| 重复时间戳 | 0 | 0 | 0 | 0 | 0 |
| OHLC 自洽违规行 | 0 | 10 | 8 | 9 | 4 |
| 非正价格行 | 0 | 0 | 0 | 0 | **1,446**（见下注） |
| 零成交量行占比 | 3.39%（无成交分钟，正常） | 0% | 0% | 0% | 0% |
| 每日 bar 数 | 240/241 | 恒 241 | 恒 241 | 恒 241 | 恒 241 |
| 整日缺失（交易日历内） | 1 天（2019-05-28） | 3 天 | 0 | 2 天 | 0 |
| 非交易日有 bar | 244 天 —— **为 2009 年全部交易日**，原因是 `reference.trade_calendar` 只覆盖 2010-01-04 起，非数据问题 | 同左 | 0 | 同左 | 同左 |

关键发现：

1. **002008.SZ 在 2015-06-05 ~ 2015-06-12（6 个交易日）被填了全零 bar**（1446 行 OHLC=0, tickvol=1）——该时段为停牌日，数据源用零 bar 填充而非跳过。**必须清洗**，否则任何基于价格的计算都会被污染。
2. **复权口径**：分钟价与 `stock_daily`（前复权）之比在每只股票上长期为常数（000002.SZ ≈1.326、000651.SZ ≈1.393、000333.SZ ≈0.0529），常数 = 文件截止日（2021-06）adj_factor 与当前（2026）adj_factor 之比。**结论：分钟数据是前复权价，锚定在各自的文件截止日**；与 DB 前复权（锚定最新）相差一个每股恒定的全局因子。000001.SZ 与 000002.SZ 的最后一天比值突变（0.976→1.20、1.326→1.62），末日价格可能未经同一口径调整，使用边界日需注意。
3. **vol 单位 = 股**：分钟 vol 聚合到日与 `stock_daily.vol`（手）之比恒为 **100.0**（多日精确 100.000）。**amount 单位 = 元**：与 `stock_daily.amount`（千元）之比恒为 **1000.0**（仅 A 型可比）。000001.SZ 个别日 vol 差 0.1–0.7%（如 2017-05-02 为 99.27），金额差最多 0.7%，属数据源间微小差异，可接受。
4. **A 型 pre_close 是未复权昨收**（如首日 pre_close=9.57 vs 复权 open=3.08，比值≈复权因子），与同行前复权 OHLC **不在同一价格基上**，不能直接用来算涨跌幅；但反过来 `pre_close / 昨日分钟close` 可作为每日复权因子的估计，有一定利用价值。pre_close 与昨日分钟收盘 mismatch 3003/3159 天，全部为上述口径差异所致。
5. 日线聚合对账（首日 open / 末日 close / max high / min low）：在复权因子换算后价格形状与 DB 一致；OHLC 聚合关系内部自洽（min_open→min_close 与 high/low 包含关系正确）。

**总体数据质量评级：B+（清洗后可用）**。扣分项：B 型缺 amount 字段、002008 停牌零填充、个别整日缺失（最多 3 天）、边界日复权口径突变、单只股票 OHLC 微违规（≤10 行）。

## 2. 适用性判断：能否作为分时回测数据源？

**结论：清洗后可用（限定范围），不宜作为主回测数据源。**

理由：

- 可清洗项（成本中等，一次性脚本可解决）：两种格式统一解析（Tab + 列名映射）、停牌零填充剔除、09:30 集合竞价 bar 口径统一、文件名代码归一化、复权因子对齐（用每日 `pre_close/昨收` 或与 DB adj_factor 比值）。
- 硬伤 1：**B 型（39/40 只股票）没有成交额字段**，任何用 amount/VWAP 的因子或策略在这批数据上不可行。
- 硬伤 2：**区间断层**。B 型统一止于 2021-06-28/29，与现有日线库（2010–2026）之间有近 5 年空白（2021-07 ~ 今），无法做近期验证或与日线因子联合的滚动研究。
- 硬伤 3：**复权锚点陈旧且每股不同**，与 DB 前复权价差一个每股恒定因子；跨股票比较、与日线因子拼接前必须重锚定，否则收益计算在跨越复权事件时仍有误差风险。
- 内存：单文件 76 万行 ≈ pandas 200–300MB（含 dt 列），引擎 `SingleSymbolBacktestEngine` 为 `iterrows()` 逐行循环，分钟级数据量比日线大约 240 倍，**单标的可跑（8898 根 1 秒内），全市场/长区间不可行**，需向量化引擎（项目内已有 `single_symbol_vectorized.py` 路线）。

## 3. 因子引擎适配结论（任务 3）

做法：复用 `indicators_tushare` 的因子类（`factors/momentum_factors.py` 的 `MACDFactor`、`RSIFactor`，均为 pandas_ta 封装），输入清洗后的分钟 OHLCV，写库 `factors_minute.test_stock_1m`（新建 schema，未碰任何现有表）。

结果：

- 000651.SZ 与 002008.SZ 各取 2021-01~2021-06（27,956 根），计算 MA20 / RSI14 / MACD(12,26,9) 并入库，共 **55,862 行写入、可读回校验通过**（`select count(*)` 及末行抽样均正确，bar_time 为 timestamptz，时区 +08:00）。
- 002008 清洗剔除 1,446 行零填充后因子正常。
- **与频率无关、直接可用**：所有 pandas_ta  rolling/ewm 类指标（MA/RSI/MACD/KDJ/布林带等 `factors/*.py` 绝大部分）——窗口语义自动从「N 日」变为「N 根 bar」，代码零改动。
- **含日频假设、需要改**：
  - `FactorTask.table_name = stock_daily_{category}_{price_type}`、`warmup=256`（按日设计）、`core/factor_base.py` 中 `trade_date` 列名归一化与 `data.index = DatetimeIndex(trade_date)`（分钟需 `bar_time`）、`enrich_price_columns` 的 `pct_chg`（日涨跌幅语义）。
  - 任何「昨日收盘 / N 个交易日 / 隔夜收益」语义的因子，分钟级需重定义（1 日 = 240/241 bar，且跨日缺口）。
  - Alpha191（`evaluation/alpha191.py`）中大量使用 `delay(x, n)`/`correlation(x, y, n)` 日窗口语义，迁移需逐因子审。

## 4. 回测引擎适配性测试（任务 4）

做法：000651.SZ 2021-05-06 ~ 2021-06-28 分钟数据（8,898 根）直接构造 engine 所需 frame（`ts_code, trade_date=分钟时间戳, open/high/low/close, vol` + 预计算 ma5/ma20），跑 `SingleSymbolBacktestEngine`，策略 `ma5 > ma20` 买 / `ma5 < ma20` 卖。

结果：引擎**未经任何修改跑通**：36 笔交易，total_return −6.18%（同期 buy&hold −12.06%），win_rate 16.7%，成本 38,935 元，无 failed_orders，权益曲线逐 bar 输出。

可直接复用的层：

- `SingleSymbolBacktestEngine.run()` 的逐 bar 主循环本质是「行驱动」，对频率无感知；
- `AShareMarketProfile` 的费用/滑点/100 股整手逻辑（`round_order_quantity`、`calculate_cost*`）；
- `evaluate_expression_signal` 信号表达式（纯列运算，频率无关）。

硬编码「日」假设（gap list）：

| # | 位置 | 假设 | 影响 | 改造量 |
|---|---|---|---|---|
| G1 | `single_symbol.py:134,214` `trade_date=trade_date.date()` | 订单日志只记日期 | 分钟级订单时间丢失（实测订单 trade_date 退化为 `2021-05-06 00:00:00`） | 小（改字段类型） |
| G2 | `holding_days` 参数语义 | 按行数计「日」 | 分钟级变成「N 根 bar」，需要时间窗语义（如「持有 3 日」= 720 bar） | 小 |
| G3 | 信号→成交固定「下一行 open」 | T+1 次日开盘 | 分钟级实际变成「下一分钟成交」，**无日内/隔夜边界处理**：14:59 出信号则 15:00 成交（收盘集合竞价不真实），跨日 T+1 规则（当日买入次日才可卖）未实现 | 中 |
| G4 | 涨跌停/停牌拦截 | 依赖 frame 里预置 `limit_up/limit_down/is_suspended` 列 | 分钟数据无这些列时全部静默放行；且涨跌停需未复权 pre_close 计算（分钟数据是复权价 + A 型 pre_close 口径不同基） | 中 |
| G5 | `data/postgres.py load_daily_bars` | 表名 `stock_daily`、`trade_date` 日期列 | 分钟数据需新数据接入层（新表/新列名 `bar_time`），引擎本身不用改 | 中 |
| G6 | 逐行 `iterrows()` | 性能按日线量级设计 | 76 万行单标的估计分钟级 × 240 时长，全市场不可行；需走向量化引擎 | 大（若求全市场） |
| G7 | 权益曲线/净值、年化等指标 | 按日频年化（`evaluation/`、组合层） | 分钟级收益率年化口径、按日切片汇总需新增 | 中 |

工作量分级总结：**单标的分钟级研究回测 ≈ 小改造（G1+G2+基础清洗接入，1–2 天）；严肃的分时回测（涨跌停、T+1、日界、真实撮合）≈ 中改造（G3+G4+G5+G7，1–2 周）；全市场分钟回测 ≈ 大改造（G6 向量化/事件驱动重写）。**

## 5. 下一步建议

1. 若要做分时回测：先补数据源（含 amount、覆盖 2021-07 至今的分钟数据，如 tushare `stk_mins` 或券商接口），当前 40 文件只适合方法验证。
2. 清洗管线固化：把 `_analysis/validate_minute.py` 的解析+清洗逻辑提为正式 ingest 脚本（格式嗅探、停牌零填充剔除、09:30 bar 口径、代码归一化、复权锚定到 DB adj_factor）。
3. 分钟因子库建议复用 `indicators_tushare` 因子类 + 新增 `bar_time` 归一化分支；入库沿用 `factors_minute.*` schema 命名规范。
4. 回测侧优先做 G1（订单时间戳保真）与 G3（日界/T+1）两项，即可支撑可信的单标的分钟级策略验证。
