# CR-2026-11-02 · NL 编译丢失“上穿/下穿/金叉/死叉”穿越语义

> 来源：2026-11-02 全期全量压测准备过程中，测试子代理在
> `docs/agent/27_STRESS_TEST_2026-11-02.md` §8.1 记录：NL 入口把“上穿/下穿/金叉/死叉”
> 编译成纯 `>` / `<` 当日状态，而不是穿越事件。本 CR 只立项和定方案，**不在 3 点压测前改业务代码**。

---

## 1. 问题

- 用户输入例如：
  - `前提SMA60大于SMA200；当SMA5上穿SMA200时买入，SMA5下穿SMA200时卖出，不设止损`
  - `macd金叉买入，死叉卖出`
- 当前 NL 编译提示词明确写道：
  - 不支持跨周期引用；
  - “上穿/下穿”请改写为当周期比较，例如 `(sma_20 > sma_120)`；
  - 并说明这是当日状态而非穿越事件。
-  few-shot 也只有当日状态比较，没有 `.shift(1)` 穿越示例。
- 结果：信号在区间内持续为真时会长开/长平，交易数与收益口径和用户语义不一致。

**根因**：不是 DSL 不能表达穿越，而是 NL prompt 主动要求降级成当日状态。DSL 已支持 `.shift(1)`，wizard 的 `crosses_above/crosses_below` 正是编译为带 `shift(1)` 的穿越事件。

---

## 2. 目标

1. NL 入口对“上穿/下穿/金叉/死叉”生成真实穿越事件：
   - 上穿：`(A > B) and (A.shift(1) <= B.shift(1))`
   - 下穿：`(A < B) and (A.shift(1) >= B.shift(1))`
2. 不改变 wizard/YAML 入口行为。
3. 不伪造因子；仍必须走真实因子目录。
4. 对“持续状态”描述（如 `rsi < 20`）保持原语义，不乱加 shift。

---

## 3. 方案

### 3.1 Prompt 层（必要）
- 修改 `gui/nl_compiler.py::_DSL_DOC`：
  - 删除“上穿/下穿请改写为当周期比较”的旧约束；
  - 增加“穿越事件必须用 `.shift(1)`”的 canonical 模式；
  - 明确“大于/小于”是当日状态，“上穿/下穿/金叉/死叉”是穿越事件。
- 增加 few-shot：
  - SMA5 上穿 SMA200 买入，下穿卖出；
  - MACD 金叉买入，死叉卖出。

### 3.2 校验/纠偏层（建议）
- 轻量规则：用户文本含“上穿/下穿/金叉/死叉”，但编译 YAML 的 entry/exit 完全没有 `.shift(1)` 时，给出 warning 或触发一次修复回路（如果现有纠错机制可复用）。
- 不强制重写所有 `>`/`<`，避免误伤“持续状态”。

### 3.3 缓存与版本
- NL prompt 变化必须 bump `NL_COMPILER_CACHE_VERSION`，避免旧缓存继续返回旧口径 YAML。

---

## 4. 实施步骤（3 点压测后）

1. 先补测试：
   - prompt 合同：包含穿越 canonical 模式；
   - few-shot 合同：包含 SMA/MACD 穿越示例；
   - stub LLM 编译穿越描述 → YAML 含 `.shift(1)`；
   - 持续状态描述 → 不乱加 `.shift(1)`；
   - 缓存版本 bump 后旧缓存失效。
2. 改 `_DSL_DOC` 与 few-shot。
3. 如做校验层，补 RED→GREEN。
4. 小样本真实 NL 编译三条：
   - SMA5/SMA200 穿越；
   - MACD 金叉死叉；
   - RSI 持续状态回归。
5. 全量测试 + 文档同步。

## 5. 风险

- LLM 可能仍不遵守 shift 模式 → 需要校验层 warning/修复回路。
- “金叉/死叉”对不同指标可能有参数默认值 → 继续依赖真实因子目录与常用列，禁止编造。
- Prompt 变化会影响 NL 缓存命中率 → 必须 bump cache version。
