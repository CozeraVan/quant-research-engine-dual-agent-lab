# CR-2026-11-19 单次回测独立权益

## 用户要求

在付费系统提供 9.9 元单次回测：每个已支付订单只可用于一次正式回测；股票数量与回测周期不受原会员范围限制；不纳入 SU 评估，也不占用会员周期次数。

## 方案比较与选择

1. **复用订单权益表（采用）**：每个 `single_full` 订单发放一条独立、可核销权益，任务记录来源订单。审计、退款和幂等沿用现有支付链，且不改变用户会员档位。
2. 在用户表增加计数字段：实现短，但订单与具体任务缺少直接关联，退款和并发审计较弱。
3. 新建完整单次钱包账本：扩展性强，但当前只有一个固定商品，属于过度设计。

## 执行合同

- SKU 保持 `single_full`，价格 990 分，开放创建订单；支付履约后增加 1 次独立权益，不把用户 tier 改为 `single_full`，不修改会员到期日。
- 正常会员范围与周期额度优先。仅当本次正式任务将因股票数/周期范围或周期次数被拒绝时，自动使用一条有效单次权益；因子字段和表数限制仍按原会员档执行。
- 单次权益在任务创建事务内行锁核销，任务记录 `entitlement_order_id`，`quota_pool='single'`；幂等重放返回原任务，不重复扣次。权益只核销一次，核销后不能再次提交。
- 使用单次权益的任务不计会员周期用量，不写 SU 影子账本。失败任务不自动返还次数，与现有提交即计次口径一致。
- 未使用权益可随模拟退款撤销；已核销权益不允许模拟退款，且单次商品退款不改变原会员档位。
- 会员中心展示剩余单次次数；9090 展示有效与已核销单次权益真实计数。
- 当前不配置真实商户、不发生真实资金操作，不启动任何回测；只使用测试库模拟支付和任务提交。

## 验证

先写失败测试，再实现并验证：9.9 元下单/履约、会员档位不变、全市场全期放行、任意小范围超限区间也可使用、只核销一次、并发与幂等、会员次数不变、SU 跳过、退款边界、会员中心及9090真实计数。
