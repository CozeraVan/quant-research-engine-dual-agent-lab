# 13_UI_PERF_NOTES.md — synthesis.html 性能评估与优化方案

> 审计对象：`/home/van/qre-outputs/ui-drafts/synthesis.html`（定稿单文件设计稿，内嵌 8081 真实数据快照）。
> 审计日期：2026-09-08。方法：静态拆解 + Node 22 纯函数基准计时 + DOM/SVG 节点静态估算（无浏览器环境，运行时数字为 Node 同算法量级估计）。本文只评估出方案，不改 synthesis.html。

## 1. 文件体积拆解

| 部分 | 大小 | 占比 |
|---|---|---|
| 总计 | 471 KB（482,466 B） | 100% |
| 内嵌 `REAL` JSON | 373.4 KB | **79.3%** |
| └ tags（归因三层） | 115.1 KB | 23.8% |
| └ symbols（5 只个股 detail） | 269.3 KB | 55.7% |
| └ chart（净值/基准/metrics） | 23.2 KB | 4.8% |
| └ runs + risk | 4.9 KB | 1.0% |
| 业务 JS（除 REAL） | 58.6 KB | 12.1% |
| CSS | 19.3 KB | 4.0% |
| HTML 骨架 | ~19.7 KB | 4.1% |

结论：体积大头是**数据不是代码**；5 只个股 detail 占一半以上。设计稿场景可接受（单文件离线是硬约束），8081 落地时必须拆开。

## 2. DOM / SVG 复杂度（各视图节点量级）

| 视图 | 主要构成 | 节点量级 |
|---|---|---|
| 新建策略 | 三入口卡 + PCB SVG（3 组×3 元素+焊盘）+ 表单 | ~150，轻 |
| 回测记录 | 9 行 × 7 列 | ~100，轻 |
| 策略详情（默认屏） | 主图 SVG（3 path + 网格 ~25 元素）、treemap 20 矩形+tooltip、指标卡 6+5 | ~120，中 |
| 策略详情（下钻后） | + 归因个股表 ≤10 行×10 列 | +100 |
| 个股明细列表 | **213 行 × 11 列 ≈ 2,343 个 td** | ~2.5k，**最重** |
| 个股详情 | K线 SVG：蜡烛 242×2 + 量柱 242 + 买卖点 104 + RSI path(242 点) ≈ 837 元素；收益曲线 3 path×242 点；交易明细 52 行 + 下单 104 行（滚动容器内） | ~1.2k，次重 |

曲线 path 本身只有 1 个节点（d 属性长字符串），SVG 字符串拼接是真开销而非 DOM 节点数。

## 3. 运行时成本热点（Node 22 基准，浏览器 V8 同量级）

| 操作 | 实测耗时 | 评估 |
|---|---|---|
| squarify treemap 布局（20 项） | 0.021 ms/次 | 可忽略；O(n·行数)，项数 ≤20 无风险 |
| 主图一次重绘计算（全期 242 点，3 path + 刻度） | 0.072 ms/次 | 纯计算极快；**真实成本在 `svg.innerHTML=` 全量重建**（字符串 ~30KB，浏览器解析+排版约数 ms） |
| 主图重绘（缩放后 60 点） | 0.018 ms/次 | 同上 |
| sliceRet 区间卡重算 | <0.001 ms/次 | 可忽略 |
| hover 十字线 | mousemove 原生频率（60–120Hz），每次只改 4 个属性 + tooltip 重排 | 轻，但 tooltip 每帧改 `innerHTML` 会触发排版，有优化空间 |
| resize | 仅 PCB 重排（3 条折线） | 可忽略 |

**热点结论**：滑块拖动的 `input` 事件每帧触发 `drawMain` 全量 innerHTML 重建（理论 60–120 次/s × 数 ms ≈ 可能掉帧）；当前数据量下实际流畅，但这是最脆弱的交互路径。

## 4. 内存评估

- REAL 解析后数值节点 ≈ 20,952 个，堆占用约 **0.3 MB**——完全无压力。
- 单条日频序列 242 点；最长结构是个股 detail（K线+因子+orders+trades ≈ 55 KB/股）。
- **上台阶风险**：若内嵌全市场 5,000 股明细 → 仅 tags 层全量 symbols 就 ~3 MB（原始 tag-analysis 实测 3.25 MB），5000 股 detail 全嵌 ≈ 270 MB，**不可行**。单文件内嵌路线只适用于"1 run + 少量个股样本"，扩量必须改架构。

## 5. 优化方案（分三档）

### 立即可做（8081 落地时顺手做）
1. **JSON 与模板分离 + 按需加载**：synthesis 内嵌 → 8081 改为 fetch 现有 API（`/api/lab/runs/<id>/chart-data` 等已是独立端点）；个股 detail 仅在进入 `#/result/symbol/<code>` 时请求。预期收益：首屏体积 471KB → ~40KB（HTML+CSS+JS），首屏时间 -90%。
2. **滑块重绘节流**：`input` 事件包 `requestAnimationFrame`（拖动期间每帧最多重绘一次）。收益：消除掉帧风险，改动 5 行。
3. **tooltip 去 innerHTML**：十字线 tooltip 改为静态 DOM 节点 + `textContent` 逐行更新。收益：hover 每帧少一次解析排版。
4. **CSS containment**：`.chart-box{contain:content}`、表格区 `contain:layout`。收益：局部重绘不扩散，大表格滚动更顺。

### 中期
5. **序列降采样/抽稀**：>600 点（多年全期）时按可视宽度抽稀（每像素 1 点，LTTB 或简单桶取），hover/区间卡用原始索引映射回原数据。收益：path 字符串长度与渲染时间随点数线性下降，5 年全期（~1200 点）可省一半。
6. **表格虚拟滚动或分页**：个股明细 213 行已 2.3k 节点；到 500 股×11 列 ≈ 5.5k 节点时首屏渲染明显变慢。先简单分页（50/页），再大再换虚拟滚动。收益：节点数封顶。
7. **treemap 懒渲染**：归因区块在视口外时 IntersectionObserver 推迟 squarify + DOM 构建。收益：详情页首屏少 ~100 节点与一次布局。
8. **K线 SVG 分层合并**：量柱合并为单条复合 path（242 rect → 1 path），蜡烛影线/实体各合并。收益：K线节点 837 → ~300。

### 上云（ECS/SaaS）前必须做
9. **明细数据服务端分页**：个股明细/交易记录改 API 分页（`/symbol/<code>/trades?page=`），前端不再一次拿全量；tags 每层每板块 symbols 服务端截断（SAAS-004 补的 `trim_tag_analysis` 已是先例）。收益：payload 与内存有界，防全市场 run 打爆浏览器。
10. **传输压缩**：API 开 gzip/br（当前 lab 未开）；chart-data 23KB → ~6KB。收益：弱网首屏关键。
11. **骨架屏**：fetch 期间显示 chart-box 骨架（灰紫渐变占位块，遵守克制原则、reduced-motion 下静态）。收益：感知性能；云端网络延迟不可控时必需。
12. **静态资源缓存策略**：模板/JS/CSS 长缓存 + 数据接口 no-cache，配合 ETag。收益：回访秒开。
13. **大数据量 fallback 纪律**：>N 点自动切 Canvas 渲染或降采样（在 style guide 空态规则基础上补一条"超量降级"），避免 SVG 节点爆炸拖垮移动端。
