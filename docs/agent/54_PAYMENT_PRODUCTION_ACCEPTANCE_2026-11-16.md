# 54. 真实支付验收门与执行手册（2026-11-16）

## 当前阻塞

生产 `/etc/qre-saas.env` 的微信商户号、AppID、商户序列号、商户私钥、平台公钥、通知地址和 API v3 密钥均未配置；备用平台公钥也未配置。因此不能执行真实证书轮换、下单、支付或退款，不能用模拟渠道替代这些验收。

## 配置就绪后的顺序

1. 备份生产 env 与支付相关文件；所有凭证只落受限 0600 文件，不打印、不入库、不入 Git。
2. 验证商户私钥与序列号匹配，平台公钥与 `Wechatpay-Serial` 匹配，通知 URL 为公网 HTTPS。
3. 配置下一平台公钥，使用真实新证书通知做轮换验收；双证书失败仍拒绝。
4. 创建一笔最小金额真实订单，核对服务端金额、订单号、二维码和30分钟过期。
5. 用户本人扫码支付；分别验证回调到达与关闭回调后的主动查单，确认只履约一次、只顺延一次。
6. 用同一订单重复通知/查单/履约重试，订单和权益计数不重复。
7. 发起全额真实退款，确认渠道成功、本地订单 refunded、权益撤销、用户回落 member。
8. 运行主动对账，确认无开放异常；再核对渠道账单与本地订单、金额、退款状态。
9. 验证另一名用户无法读取或操作该订单；9090 的订单、权益、退款和对账计数与数据库一致。

## 停止与回滚

任何金额不符、重复履约、越权、验签失败放行或退款未降级都立即停止真实验收。代码回滚点为 `/tmp/qre-deploy-20261116T122017Z.bak`；配置回滚使用验收前新建的 env 备份。真实资金异常先停止新订单并保留全部审计证据，不通过修改数据库掩盖渠道差异。
