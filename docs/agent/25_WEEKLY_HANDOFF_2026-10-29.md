### 2.1 【最严重】直接修改了数据库里的行情数据

修 `920832` 年化 `3.576778280587912e+35%` 时，改的是 DB 里的行情数据本身，

**纪律**：生产/研究数据**只读**；口径错就修计算与呈现，**绝不改源数据**。
**复查**：`git log` 里涉及 UPDATE/覆写行情表的提交全部过一遍，确认没有残留的
数据层修改；若发现，评估是否需要从备份恢复。

### 2.2 年化收益爆表 bug 未排查彻底

- 已修：`a1516f0`（持仓期年化分母 + 除零保护）、`1ad14d6`（加完整年度下限，
  修 920556 爆表）、58 号任务的 `920832`。
- **2026-10-29 实测**：底层 API 已正常——job 58/920832 `total_ret_pct = 5.29%`、
  job 66/920556 `= 9.46%`，响应里无科学计数法。
- **仍待做**：年化值是**前端现算**（`24_PERF_METRICS_CONTRACT.md`），
  API 正常 ≠ 页面正常，需一次真实浏览器目视；并全库扫极值兜底。
  修法必须是计算侧兜底（分母下限/截断），**不是改数据**（见 2.1）。

### 2.3 统计口径失准只修了两个任务

用户原话：「因统计口径导致的收益率失准是否已经应用到全局？对于历史已完成的回测结果
是否能够显示正确的收益率」→ 结论是只修 58/66，其余历史任务**未修、未重跑**，
且用户后来删除了除 58/66 外的所有回测测试数据。
**复查**：确认新口径已在引擎全局生效（新任务全部正确），
并在文档里写清"历史任务要么重跑要么标注旧口径"，避免用户看到旧数字以为又坏了。

### 2.4 技术指标复权问题**多次复发**（治标不治本）

用户原话：「这个问题已经出现了多次，每次都是治标不治本」。
症状：个股详情里 EMA/BOLL 等价格型因子与 K 线严重偏离（#78 `600330`、
小游戏里 K 线 OC LH≈5 而 EMA/BOLL 飙到 27-30）。
已知机制：因子表 hfq、K 线 qfq@末日，缺 `factor_basis` 的旧快照会把因子按 hfq 尺度
与 qfq K 线并列（`app.py` 已对这类快照拒绝下发）。
**复查（高优先）**：把 `factor_basis` / 复权锚点做成**硬契约**——
生成侧必须写、读取侧缺了就拒绝 + 告警；归档的 496 个旧产物要标注口径未知。

### 2.5 FRM 波动率模块改出回归

且"低/中/高波动率股票数几次回测都是均匀的"疑似数据错误；

### 2.6 平均持股周期曾显示无数据

### 2.7 《我不是股神》小游戏：指标错乱 + 布局不合交易软件直觉

Kimi 与 DeepSeek 两版都不合格（用户原话「和你和 DeepSeek 大差不差」）：
技术指标与 K 线尺度错乱、指标没有 overlap 到 K 线上、操作与 K 线生长时机脱节。
**现状：挂起**。根因与 2.4 同源——**每次新场景调用 K 线+因子都会重新踩复权/呈现的坑**。
**复查**：恢复开发前必须先落实 2.4 的硬契约，并直接复用 `factor-layout.js` 的呈现层，
不要第三次重写。

### 2.8 子 agent 交付质量不稳定，验收不严就部署过

- DeepSeek UI 三版本色板重装修**全部不通过**（已停案、恢复原色板、删缓存、停监听端口）；
- step5 侧边栏胶囊**缺沿移动方向拉长的特效**（返工一次才过）；

- DeepSeek 小游戏优化版"bug 多得我不想再提"，全盘抛弃。
**教训（已部分固化）**：① 派活必须给**可判定的验收标准**；
② 先小范围样本验证再全量；③ 子 agent 崩没崩要看 CR 是否落盘。

### 2.9 两个环境坑（已修，写在这里防再犯）

- **`/etc/systemd/system` 下的 unit 是副本**：只改仓库 unit + `daemon-reload`
  **不生效**（`systemctl show` 仍显示旧值），必须 `cp` 覆盖再 reload。
- **`.gitignore` 的 negation 行尾不能带 `#` 注释**：git 不支持行尾注释，
  会把注释吃进 pattern，导致 negation 静默失效（用 `git check-ignore -v` 复验才发现；
  注意它对 negation 命中也会退 0 并打印 `!` 行，**脚本化判定要用 `git add -n`**）。

### 2.10 夜间模式暂停初版只夹了一半

只夹 `resolvedTheme()` 不够——`toggle → set('dark')` 会绕过（实测过），
必须同时夹 `set()`。同类"看起来改了其实有旁路"的坑，改开关类需求时要把**所有入口**枚举一遍。

### 2.11 分享链接曾 500 + 生成后不可用

分享创建 HTTP 500、以及生成出的 `/saas/jobs/78?share=...` 打开无效，均已修。
**复查**：回归一次分享创建 → 打开 → 权限隔离（见 2.12）。

### 2.12 回测详情隐私隔离（已 brainstorm 计入 todolist，**未确认是否已完工**）

76 号私人回测曾可被未登录游客直接打开。
