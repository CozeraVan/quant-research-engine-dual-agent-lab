## Risk-Control Exit Rules

For the first implementation:

- Only shared-cash portfolio engine is in scope.
- Stop loss and take profit are percentages relative to entry price. This is implemented.
- Long-only assumptions:
  - stop loss triggers when current bar low is at or below `entry_price * (1 - stop_loss_pct)`.
  - take profit triggers when current bar high is at or above `entry_price * (1 + take_profit_pct)`.
- If both trigger on the same daily bar, choose stop loss first as the conservative daily-bar assumption.
- Risk exits are checked before fixed holding-period exits.
- If the resulting sell order is blocked by market profile validation, keep the position and try again on later bars.

Implemented trailing-stop rule:

- Trailing stop should track the highest available favorable price since entry.
- For daily long-only bars, use current/past `high` to update the trailing anchor.
- Trigger when current bar `low <= trailing_anchor * (1 - trailing_stop_pct)`.
- If stop loss, take profit, and trailing stop collide on the same daily bar, keep conservative ordering:
  1. stop_loss
  2. trailing_stop
  3. take_profit
  4. holding_period
- Record `exit_reason=trailing_stop`.

Implemented YAML risk-control parsing:

- Parse risk-control fields from strategy YAML.
- YAML location:
  - `risk.stop_loss_pct`
  - `risk.take_profit_pct`
  - `risk.trailing_stop_pct`
- CLI explicit risk flags override YAML values.
- Absent CLI risk flags use YAML values.
- Absent YAML values remain `None`.

Implemented YAML weight-model parsing:

- Parse shared-cash weighting fields from strategy YAML.
- YAML location:
  - `portfolio.weight_model`
  - `portfolio.score_column`
  - `portfolio.volatility_column`
- CLI explicit weight flags override YAML.

Implemented rebalance framework:

- long-only
- shared cash only
- fixed interval by trading-day count
- rebalance existing positions toward target weights
- rebalance does not create positions without an entry signal
- no industry/index constraints until metadata is ready

## Rebalance Rules

First implementation target:

- Disabled by default. Implemented.
- Configured by `rebalance_interval_days`. Implemented in request, YAML, and CLI.
- Only applies to the shared-cash portfolio engine. Implemented.
- Rebalance trigger is based on simulated trading-day count after the first bar. Implemented.
- Rebalance uses current bar mark prices and current cash/equity only. Implemented.
- Existing positions are adjusted toward target weights generated by the existing weight model. Implemented.
- The first pass avoids extra strategy semantics:
  - do not open new symbols only because rebalance is due
  - do not close positions only because their signal disappeared
  - keep risk-control and holding-period exits as separate exit logic
- Rebalance orders pass the same market-profile validation and cost/slippage logic as normal orders.
- Rebalance orders are tagged with `reason=rebalance`.

Implemented rebalance summary metrics:

- Metrics scope:
  - `rebalance_order_count`
  - `rebalance_notional`
  - `rebalance_cost`
  - `rebalance_turnover`
- `rebalance_turnover` is rebalance notional divided by average total equity over the simulated equity curve.

Implemented richer fill accounting for partial rebalance sells:

- Rebalance sell accounting scope:
  - generate `trades` rows with `exit_reason=rebalance`
  - consume lot cost basis FIFO
  - preserve remaining position quantity and remaining entry cost after partial sell
  - remove the position if quantity reaches zero
- Rebalance buys should keep increasing weighted average entry price and accumulated entry cost.

Implemented sellable inventory:

- Position accounting stores entry/rebalance fills as lots.
- Each lot records quantity, entry price, entry date, entry cost, and entry bar index.
- Sell logic only sells lots with `entry_bar_index < current_bar_index`, matching A-share T+1 sellability for daily bars.
- Rebalance cannot sell a lot bought earlier on the same trading day.

Implemented failed rebalance diagnostics:

- Failed rebalance diagnostics scope:
  - count failed orders with `reason=rebalance`
  - sum their attempted notional
  - preserve existing `failure_reason` values in `failed_orders`
